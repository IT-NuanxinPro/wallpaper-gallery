# 首屏加载与自有图片入口实施计划

## 目标与边界

沿用用户已确认的方案：最新切片先展示，后台补齐完整数据；缩略图和预览图走自有图片入口。此次从项目入手，不修改数据库、不操作服务器、不提交或创建分支，不直接发布生产。

## 设计

- 普通系列并行读取 latest 与 index；latest 可用即可展示，完整分类数据完成后一次性合并替换。Bing 使用独立的日期转换逻辑。
- 保留 initSeries 等待完整加载的调用约定，通过 store 的 loading/currentRenderedSeries 状态解除首屏遮罩。完整数据尚未就绪时，筛选/非默认排序不展示不完整结果。
- 缓存与请求代次共同隔离切换系列、手动刷新及过期响应。切片失败仍可从完整数据加载；补全失败保留已展示内容并给出重试入口。
- 图片入口使用本站 /images/{tag}/thumbnail|preview/{series}/{path}，由 Cloudflare Pages Function 提供。只允许固定 GitHub 图源和静态图片目录，返回图片实体，缓存成功图片，拒绝任意URL代理。
- 前端图片基址可配置，原图/下载及现有 Bing、R2 视频地址保持原有来源。代理失败先回退同尺寸直连资源，最后才回退大图。
- Vite 开发和预览使用相同的图片处理函数，生产仅 /images/* 经过 Pages Function，其他静态路径继续由 Pages 提供。

## 实施与验收

- [x] 1. store：先编写慢分类、latest失败、后台失败、切换与刷新竞态、Bing最新切片的行为测试，再实现分阶段加载。
- [x] 2. 图片入口：编写路径验证、GET/HEAD、实体返回、缓存命中、错误不缓存、超时与大小限制测试，再实现固定上游代理和本地适配。
- [x] 3. 前端：统一缩略图/预览图入口与回退；补充图片路径编码回归，保持原图下载行为。
- [x] 4. UI集成：首屏就绪立即展示；非默认筛选等待完整数据；补全失败可重试；保持当前视觉设计。
- [x] 5. 联合验证：测试、ESLint、生产构建、Pages Function构建；在本地以受控慢请求验证切片先于完整数据显示，并检查实际图片与代理缓存。
- [x] 6. 独立复核、保存测量结果及运行说明；明确本地完成与未发布状态。

## 测量方法

使用同一份当前线上快照构造可控网络响应，将完整分类固定延迟而 latest 立即完成；记录首屏可见、完整数据就绪时间及初始图片请求路径。此结果说明加载依赖变化，不当作大陆真实用户速度指标。实际图源仅进行有限只读请求。
