# 统计口径与资源身份

自 v5.1.1 起，网站访问分析、图片预览和下载发起是三个独立指标。

- 网站 PV/UV 由现有网站分析服务提供。
- 图片或视频实际就绪且详情打开时记录预览；同会话、同资源 10 分钟内重复预览不累加。
- 浏览器已触发下载或原生桥确认保存时记录下载发起；空文件、错误页、失败和只打开备用链接不计数。浏览器不能证明最终文件保存成功。
- 事件重试复用 ID；服务端以事件 ID 幂等，并执行会话窗口去重与请求上限。匿名会话不能当成可靠身份或完整防刷手段。
- 本周、本月热门使用北京时间周一、每月一日起的预览和下载增量，分数为预览数加两倍下载数，与资源上传日期无关。
- 历史累计保留，期间统计从新机制启用后积累，不反推或补造历史每日记录。

## 资源身份

静态图片和视频采用 `series:path:<规范化完整资源路径>`，每个路径段统一编码；Bing 继续使用日期键。计数、喜欢、收藏、资料库和导出均使用完整键，不能只按文件名关联。

旧同名资源的浏览/下载已经混合，无法可靠拆分；迁移保留旧键为独立历史累计。已有用户关系跟随数据库原本 `source_path` 对应资源，缺失的同名资源补入目录，后续分别计数。

## 导出与缓存

`get_stats_page` 使用稳定游标分页。客户端一直读取到空页，并校验总条数、周/月起点一致；任一请求失败或期间跨界，整套快照不替换旧文件。静态 schema 2 包含 `rowCount`、`exportedAt`、`periodStartedAt`、`weekStart`、`monthStart` 和完整计数。

页面跨周/月后使旧期间分数失效；更新快照后恢复期间排名。静态快照存在更新延迟，不能把每次点击后数字不立即变化当作数据库写入失败。

## 迁移与部署

迁移主体：`scripts/migrations/20261109_statistics_v2.sql`。

生成完整迁移：`node scripts/prepare-statistics-migration.js <完整元数据目录> <证据输出目录>`。证据目录需包含经只读导出的 `assets-before.json`，字段为 `asset_key,series,filename,source_path,status`。生成器会输出具体 SQL 和映射清单，主体文件不能脱离其暂存数据单独执行。

迁移前锁定并校验资产路径指纹，在非公开 schema 中备份资源、统计和关系表；外键更新级联保留用户数据，累计浏览/下载必须与备份相等。迁移主体增加事件与每日统计、分页 RPC、资源身份约束，并收紧个人资料敏感列权限。

数据库、新前端及同步脚本必须配套切换。旧页面需要刷新；旧文件名同步会被约束拒绝，不能继续用旧版本脚本覆盖新数据。上线后先验证备份、资源数量、累计守恒、关系计数及角色权限，再检查静态统计和站点版本。
