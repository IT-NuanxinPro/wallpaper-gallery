# 自有图片入口

前端缩略图、预览图默认使用本站 `/images/`。入口返回图片实体，固定从 GitHub Raw 拉取，不返回 jsDelivr 重定向，也不接受任意远程 URL。

## 路径合同

```text
/images/{tag}/{thumbnail|preview}/{desktop|mobile|avatar}/{path}
```

示例：

```text
/images/v1.2.63/thumbnail/desktop/动漫/01_%23wallpaper%20美图.webp
```

对应固定上游：

```text
https://raw.githubusercontent.com/IT-NuanxinPro/nuanXinProPic/v1.2.63/thumbnail/desktop/%E5%8A%A8%E6%BC%AB/01_%23wallpaper%20%E7%BE%8E%E5%9B%BE.webp
```

- tag 接受 `v1.2.63`、`v1.2.63-rc.1` 等版本，拒绝分支名。
- 扩展名允许 AVIF、BMP、GIF、ICO、JPEG、JPG、PNG、WebP，并且上游必须返回对应的栅格图片 Content-Type；SVG、HTML 不允许。
- 文件名中的井号、空格、问号需要分别编码为 `%23`、`%20`、`%3F`。已有编码只规范化一次，不反复解码字面量百分号。
- 拒绝查询参数、空路径段、路径穿越、编码斜杠、反斜杠、控制字符、远程 URL。
- 原图下载、Bing、R2 视频仍由各自现有来源提供。

## 本地开发与预览

`build/vite-plugin-image-proxy.js` 导出 `viteImageProxyPlugin`，在 `vite.config.js` 的插件数组中启用：

```js
import { viteImageProxyPlugin } from './build/vite-plugin-image-proxy.js'

// 合并到项目现有 plugins 数组。
plugins: [viteImageProxyPlugin()]
```

`pnpm dev` 和 `pnpm preview` 都使用与 Pages 相同的 `handleImageRequest`。本地内存缓存最多保留 128 张、总计 32 MiB，按最近使用顺序淘汰；重启进程会清空缓存。

## 配置独立图片域名

`VITE_IMAGE_BASE_URL` 是完整的图片入口前缀。默认 `/images`；另一站点部署同一 Function 时，配置为 `https://images.example.com/images`，保留末尾的 `/images`。这些 Vite 环境变量在构建时生效，修改后需要重新构建。

前端只接受 `/images` 或 `https://域名/images`（末尾可带斜杠），与 Function 和本地插件监听的 `/images/*` 保持一致。裸域名、其他路径前缀、HTTP、带凭证或查询参数的配置都会回退本站 `/images`；单独修改前端配置不会创建新路由。

成功图片、缓存命中、HEAD 和 304 均返回 `Access-Control-Allow-Origin: *`，供 `crossorigin="anonymous"` 的图片与 canvas 裁剪使用；不返回 `Access-Control-Allow-Credentials`，也不向图源转发凭据。该入口只提供固定公开图源。普通图片 GET/HEAD 不需要预检；入口仍仅允许 GET/HEAD。

## Cloudflare Pages

1. 在项目根目录执行 `pnpm build`，静态输出目录仍为 `dist`。
2. `functions/images/[[path]].js` 必须随项目源码进入 Pages 构建。根目录 `functions` 是 Pages Functions 的源目录，不需要复制到 `public`。
3. `public/_routes.json` 会进入 `dist/_routes.json`，只将 `/images/*` 交给 Function；其他路径保留静态 Pages 服务。
4. 使用项目现有 Wrangler 安装在仓库根目录验证 Function 构建：

   ```sh
   wrangler pages functions build "functions" --outdir "output/pages-image-function-check"
   ```

5. 正式发布时需要支持 Pages Functions 的 Git 构建或 Wrangler 发布流程。只拖入静态 `dist` 文件的发布方式不会编译根目录中的 Function；发布后 `/images/` 返回 SPA HTML 即表示入口未生效。

Function 使用 `caches.default` 缓存成功 GET，通过 `waitUntil` 写缓存。缓存只在命中的 Cloudflare 数据中心生效，冷请求仍依赖 GitHub Raw；本地缓存命中不代表生产已命中，也不代表大陆网络下的真实速度。

## 响应与边界

- 仅允许 GET、HEAD；HEAD 命中 GET 缓存时复用响应头，没有响应体。
- 成功返回 `Content-Type`、上游 `ETag`（若提供）、`Content-Length`、`X-Content-Type-Options: nosniff` 和一年公开不可变缓存策略。
- `X-Image-Cache: HIT|MISS` 表示入口缓存情况；`If-None-Match` 匹配时返回无实体的 304。
- 版本化路径按不可变资源处理，修改已有图片内容时必须更换 tag；同一 tag 上覆盖图片不会主动刷新缓存。
- 请求与读取图片流合计最多 10 秒，单张最多 5 MiB。流完整且限制检查通过后才返回或缓存，避免缓存截断图片。
- 上游 404 返回 404，其他非 200、非栅格响应、重定向与超大图片返回 502，超时返回 504；错误统一 `Cache-Control: no-store`。
- 不转发访客 Cookie、Authorization、Range，也不转发上游 Cookie、Location 或错误正文。缓存读写故障不会阻止正常上游返回。

## 验证

```sh
pnpm exec vitest run "tests/image-proxy.test.js"
pnpm exec eslint "server/image-proxy.js" "build/vite-plugin-image-proxy.js" "functions/images/[[path]].js"
```

测试使用真实 Fetch API 和本地 HTTP 服务，只替换外部上游响应。覆盖固定上游映射、路径拒绝、缓存、HEAD/304、错误不缓存、10 秒连接/流超时、5 MiB 限制及本地缓存容量。项目代码完成不等于远程发布；发布与真实网络测速需要单独执行。
